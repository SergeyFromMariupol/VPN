# VPN

Установщик самостоятельного VPN для **чистой Ubuntu 24.04 LTS x86_64**.
3X-UI управляет пользователями, Xray принимает VPN. При выборе Cloudflare WARP
он даёт отдельный выход в Интернет. Домашняя сеть и дополнительные панели не нужны.

## Установка

Нужны VPS с собственным публичным IPv4 и доступ root. **Домен необязателен.**
IP и сетевой интерфейс установщик определяет автоматически.

- **По доменному имени:** выберите пункт `2` и укажите домен. Заранее создайте одну DNS A-запись
  на IPv4 VPS, удалите AAAA. В Cloudflare выберите **DNS only**.
- **По IP-адресу:** выберите пункт `1` или нажмите Enter в меню адреса.
  Панель, подписка и профили используют IPv4 VPS.

Сначала мастер спрашивает, какие профили показывать в одной подписке:

| Набор | Использовать CloudFlare WARP | Не использовать CloudFlare WARP | Оба варианта профилей |
| --- | ---: | ---: | ---: |
| Основные | 3 | 3 | 6 |
| Для DPI/ТСПУ | 49 | 49 | 98 |
| Все проверенные рабочие | 73 | 73 | 146 |

В наборы 98 и 146 входят исходные шесть профилей; в наборы 49 и 73 —
соответствующие три профиля выбранного выхода. Дополнительные профили
различаются протоколом, транспортом, защитой или режимом: это 70 отдельных
конфигураций с двумя вариантами серверного выхода, а не 70 копий на разных
портах. Наборы основаны на проверках через мобильную сеть Miranda и Happ;
доступность на других сетях проверяется после установки. При варианте 1 в
подписку попадают только профили с серверным выходом через WARP. Вариант 2
устанавливает прямые профили без WARP. Вариант 3 даёт оба выхода в подписке.

Установщик всегда выпускает доверенный сертификат Let’s Encrypt для выбранного
IP-адреса или домена. Панель и подписка работают по HTTPS; все профили
выбранного набора остаются доступны.
Контактный email для Let’s Encrypt можно указать в мастере или оставить пустым.

Разрешите нужные порты также в firewall/security group провайдера VPS.

Подключитесь к VPS по SSH и выполните:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/SergeyFromMariupol/VPN/main/install.sh)
```

Откроется цветной мастер. Ниже показаны числа для пункта 3; после выбора
пункта 1 или 2 мастер показывает 3, 49 и 73 профиля:

```text
VPN · 3X-UI
REALITY · Hysteria2 · XHTTP

[Выход] Использование CloudFlare WARP

  1. Использовать CloudFlare WARP
  2. Не использовать CloudFlare WARP
  3. Оба варианта профилей

[Профили] Сколько вариантов установить

  1. Основные 6
  2. Для DPI/ТСПУ — 98
  3. Все проверенные рабочие — 146
  4. Выбрать вручную — любые позиции из каталога для выбранного выхода

[VPN] Адрес подключения

  1. По IP-адресу
  2. По доменному имени

[?] Выберите вариант [1]:
```

При выборе пункта `4` мастер показывает список с галочками. Стрелки перемещают
курсор, пробел отмечает профиль, Enter подтверждает выбор, Esc отменяет запуск.
Для длинного списка используйте Page Up и Page Down. Если терминал не
поддерживает интерактивный список, мастер принимает номера и диапазоны,
например `1, 4, 8-10`. В подписку попадут только выбранные позиции.
`--resume` использует сохранённый список.

Сначала выберите выход и набор, затем способ подключения. Вариант адреса `1`
использует IP сервера; для варианта `2` нужно ввести доменное имя. Далее
появится меню REALITY:

```text
  1. Свой сайт — self-steal
  2. Свой сайт-заглушка + другой SNI клиента
  3. Внешний сайт — ввести SNI вручную
```

По умолчанию выбран self-steal: собственный домен становится SNI, а локальный
HTTPS-сайт — целью REALITY. Если выбран адрес по IP, этот вариант попросит
домен для сайта, панели и подписки. Во втором варианте можно оставить адрес
по IP и вручную задать SNI клиента. Сертификат заглушки будет доверенным
сертификатом своего IP или домена. `max.ru` больше не подставляется автоматически;
его можно ввести вручную.

Обычное TLS-подключение к REALITY-порту по IP, домену, с посторонним SNI или
без SNI получает заглушку со своим сертификатом. Авторизованный клиент проходит
проверку ключом REALITY. Если SNI клиента отличается от имени в сертификате
заглушки, обычный браузер/сканер обнаружит несовпадение имени; для чужого
домена доверенный сертификат не выпускается. Клиентский SNI остаётся видимым
в ClientHello: заглушка не гарантирует снятие ограничений хостера или ТСПУ.

Третий вариант сохраняет обычный внешний target: SNI проверяется сразу на
TLS 1.3, H2, доверенную цепочку и совпадение имени. В этом режиме постороннему
подключению доступен ответ внешнего сайта. У локальных вариантов TLS проверяется
после выпуска сертификата и запуска заглушки, до создания VPN-профилей.
Локальный сайт слушает только `127.0.0.1:9443`, новые публичные порты не открываются.
Сохранённые установки без поля режима остаются внешними; `--resume` не меняет SNI.

После установки введите `vpn`, чтобы открыть меню управления. Через него можно
проверить VPN, показать свои реквизиты, поменять режим REALITY и клиентский SNI,
посмотреть папку сайта, восстановить стартовую страницу или включить PHP.
Смена SNI сохраняет существующие ключи и подписку; после неё обновите подписку
в приложении. Перед изменением создаётся закрытый снимок, а ошибка проверки
вызывает откат.
Если изменение прервалось и осталось незавершённым, меню сообщит об этом;
для проверенного восстановления есть `vpn recover`. При жёстком отключении
внутри ещё не завершённой подготовки сайта может потребоваться восстановление
из закрытого снимка: утилита сохранит состояние и остановится.

Сайт расположен в `/var/www/vpn-decoy/public`. При установке туда помещается
обычный `index.html`. Свои HTML, CSS, JavaScript, изображения и другие файлы
можно загрузить в эту папку через SFTP. Они будут открываться по `https://IP`
или `https://домен` на порту REALITY в локальных режимах. Для доверия браузера
используйте адрес, включённый в сертификат: сертификат одного домена не
подтверждает произвольное другое имя. Публичный HTTP/80 остаётся для ACME.

PHP включается отдельным пунктом меню и обслуживается локальным PHP-FPM
под отдельным пользователем. До включения PHP файлы `.php` не выдаются как
обычный текст. После включения PHP приоритет получает `index.php`. При
восстановлении заглушки прежние `index.html` и `index.php` сохраняются в
закрытом снимке, а стартовой страницей становится обычная HTML-заглушка.
Остальные файлы сайта сохраняются на месте.

Затем мастер просит **ваше имя** для
начала названий профилей; оператор связи в названия не подставляется. Затем
можно указать контактный email для Let’s Encrypt. После этого установка
идёт автоматически: проверка сервера, `apt-get update`,
`apt-get upgrade -y --no-remove` и настройка VPN.
**Все новые профили без ограничения IP и устройств**.
SSH-порт берётся из текущего подключения; при запуске из консоли его нужно
указать отдельно. Обрыв ввода или неверный домен останавливают запуск
до обновления пакетов.

Во время установки видны полоса выполнения, текущий этап и прошедшее время.
Индикатор обновляется каждую секунду, в том числе при долгом обновлении Ubuntu
или загрузке компонентов. Строка «Общий прогресс» показывает долю завершённых
этапов всей установки; продолжительность этапов может различаться. Успешный
этап отмечается отдельно знаком `✓`. `100%` появляется после итоговой проверки.
Проверки SNI, сервера и подготовка установки показывают индикатор, время и
результат без процентов. При `--resume` учитываются уже завершённые этапы.
Для стандартных шести профилей выполняются 12 этапов, в IP-режиме 13. Выбранный одиночный
выход и расширенный набор добавляют
этапы проверки, настройки и публикации.
Вне терминала выводятся обычные строки начала и завершения этапов.

Команда работает от `root` через Bash. Цвета отключаются при `NO_COLOR`,
`TERM=dumb` или выводе вне терминала. Для загрузки установщика и его исходников пакеты не ставятся;
`curl`, если его нет, установится вместе с остальными зависимостями во время
установки. Завершённые обновления
системных пакетов сохраняются, даже если последующий этап VPN потребует повтора;
план и версии пакетов записываются в закрытый снимок.
Если dpkg занят фоновым обновлением, установщик ждёт до трёх минут;
локально изменённые конфигурации пакетов сохраняются.
Перед изменениями установщик проверяет
чистоту сервера, DNS домена (если указан) и TLS 1.3/H2 выбранного REALITY target.
Для Let’s Encrypt используется HTTP-01 на TCP80.

Если в образе нет `curl`, используйте загрузку через стандартный Python 3:

```bash
python3 -I -c 'import pathlib,urllib.request as u; o=u.build_opener(u.ProxyHandler({}),type("NoRedirect",(u.HTTPRedirectHandler,),{"redirect_request":lambda *a,**k:None})()); pathlib.Path("/root/vpn-install.sh").write_bytes(o.open("https://raw.githubusercontent.com/SergeyFromMariupol/VPN/main/install.sh",timeout=60).read(1048576))' && bash /root/vpn-install.sh
```

После установки терминал покажет:

```text
PANEL_URL=https://<домен-или-IP>:2053/<случайный-путь>/
PANEL_USERNAME=<новый-логин>
PANEL_PASSWORD=<новый-пароль>
SUBSCRIPTION_URL=https://<домен-или-IP>:2096/<случайный-путь>/<идентификатор>
```

Импортируйте **SUBSCRIPTION_URL** в актуальный v2RayTun, Happ или Karing.
При выборе обоих выходов и основного набора подписка содержит шесть профилей
в таком порядке (вместо «Сергей» будет введённое вами имя):

1. Сергей · ☁️ Cloudflare · REALITY
2. Сергей · ☁️ Cloudflare · HYSTERIA2
3. Сергей · ☁️ Cloudflare · XHTTP
4. Сергей · 🖥️ IP сервера · REALITY
5. Сергей · 🖥️ IP сервера · HYSTERIA2
6. Сергей · 🖥️ IP сервера · XHTTP

У дополнительных профилей после такого же начала указаны протокол, транспорт,
защита и применимые режимы. Маркеров `TEST` и номеров опытов в названиях нет.

Каждая **новая установка на чистом сервере** создаёт случайные логин, пароль,
пути панели и подписки, subscription ID и ключи клиентов. Действующие реквизиты
другого сервера не переиспользуются. `--resume` продолжает ту же установку
и сохраняет её реквизиты; `--show-access` только показывает их.

Профили Cloudflare выходят через серверный WARP; профили «IP сервера» — через
физический IPv4 VPS. Если WARP перестаёт
работать, Cloudflare-профили закрываются с ошибкой; перехода на IP VPS нет.
Название Cloudflare относится к выходу WARP. Клиент подключается к VPS.

### Смена IPv4 и несколько адресов

В IP-режиме таймер проверяет назначенные серверу публичные IPv4 примерно раз в
три минуты. Основным считается IPv4, который ОС выбирает для исходящего трафика
по основному маршруту. Остальные публичные IPv4 на том же интерфейсе могут
принимать подключения к VPN и отдавать ту же подписку. Назначение IP в панели
провайдера и настройка сети VPS выполняются владельцем. Для каждого адреса
провайдер должен пропускать TCP80 для Let’s Encrypt, TCP2096 для подписки и
порты выбранных профилей для VPN.

При изменении набора адресов установщик запрашивает сертификат с этим набором
IPv4, проверяет подписку и переключает конфигурацию. Путь подписки, ключи,
пароли и порядок профилей сохраняются. Панель доступна на основном IP.
Профиль «IP сервера» выходит в Интернет через основной исходящий IPv4, даже
если клиент подключился к дополнительному адресу.

Если старый IP ещё назначен VPS, подписка по нему продолжит работать. Для
подключения через дополнительный IP замените только адрес перед `:2096` и
обновите подписку в приложении. Если старый IP отключён, один раз замените
адрес в сохранённом URL. Актуальные реквизиты показывает команда:

```bash
sudo bash /opt/vpn-installer/install.sh --show-access
```

Запустить сверку сразу после смены IP можно через
`sudo systemctl start vpn-ip-address.service`. Статус последней попытки виден в
`sudo journalctl -u vpn-ip-address.service -n 20`. Если Let’s Encrypt не может
достучаться до нового адреса, сервер сохраняет предыдущую конфигурацию и
повторяет попытку. При переключении возможен короткий перерыв VPN.
Автоматизация устанавливается при новой установке с этой версией исходников.

### Маршрутизация на устройстве

Новая подписка называется **GitHub VPN** на странице в браузере и в клиентах,
которые поддерживают название подписки. Happ, INCY и v2RayTun получают профиль
маршрутизации с именем, указанным в мастере установки. Российские домены и IP, а также локальная
сеть идут напрямую через подключение устройства. Остальной трафик использует
выбранный VPN-профиль.

Установщик передаёт список обхода в подписке для INCY и Happ на Android.
INCY применяет список автоматически. Happ получает список даже с пустым
Provider ID, а для автоматического применения нужен премиальный **Provider ID**,
зарегистрированный для адреса подписки. В Happ, v2RayTun и Karing список также
можно импортировать из буфера. На странице подписки в браузере есть кнопка
копирования списка. Откройте ссылку сайта в подписке Happ или INCY
либо нажмите объявление со списком в v2RayTun. Для любого клиента доступен
[TXT со всеми пакетами](bundle/scripts/android-app-bypass.txt). [Инструкция](docs/android-app-bypass.md)

## Что устанавливается

| Компонент | Версия / транспорт |
| --- | --- |
| 3X-UI | 3.11.0, непривилегированный пользователь xui |
| Xray | 26.10.21, проверка SHA-256 до установки |
| WARP | Только для вариантов 1 и 3: 2026.7.1377.0, отдельный network namespace |
| Certbot | 5.9.0, отдельное Python-окружение, зависимости закреплены SHA-256 |
| REALITY | VLESS/gRPC TCP443, chrome, без flow |
| Hysteria2 | UDP443, доверенный TLS, ALPN h3 |
| XHTTP WARP | Только для вариантов 1 и 3: VLESS/REALITY TCP8443, server auto / client stream-one |
| XHTTP direct | VLESS/REALITY TCP8444, server auto / client stream-one |
| Панель | HTTPS2053, Nginx, случайный путь; backend на loopback |
| Подписка | HTTPS2096 |

XHTTP работает отдельными службами с MSS1200: для варианта 2 — direct,
для вариантов 1 и 3 — direct и WARP. Панель управляет основной
базой и REALITY/Hysteria2; конфигурации отдельных XHTTP-служб хранятся отдельно.
Изменение их ключей/пути через обычный inbound панели не обновляет эти службы;
их трафик также не включается автоматически в счётчики панели.
В расширенных наборах дополнительные варианты работают в отдельной Xray-службе
и добавляются как ссылки в ту же подписку 3X-UI. Изменение только записи ссылки
в панели не меняет соответствующий Xray inbound.
Установщик сначала создаёт базовую схему, затем транзакционно переводит XHTTP
в окончательную схему REALITY на порту 8444 (и 8443 при выборе WARP)
и проверяет выдачу подписки.

При выборе WARP он поддерживает TCP/UDP/DNS. Default route хоста сохраняется. Отдельный watchdog
запускает проверку настоящего HTTPS payload с интервалом 14 секунд от начала
предыдущей; при сбоях проверка и восстановление могут занять дольше. WARP
восстанавливается отдельно после трёх отказов, с паузой между восстановлениями
не меньше 120 секунд.
Сервисы включаются в systemd. Certbot обновляет сертификат, deploy hooks
атомарно переключают его рабочую копию и перезапускают нужные службы.
Независимый таймер повторяет сверку сертификата каждый час: если Certbot уже
продлил сертификат, а переключение рабочей копии не удалось, попытка повторяется
без нового выпуска сертификата. Недоверенный сертификат, неверное имя/IP,
истекающий сертификат или несовпадающий ключ не переключаются.
IP-сертификат выпускается с профилем `shortlived` (около шести дней).
Таймер проверяет продление каждый час; TCP80 должен оставаться доступным
для повторной проверки IP/домена. Почта и сертификаты относятся к тому, кто
устанавливает VPN. Самоподписанные сертификаты и `insecure=1` не используются.

Входящие порты: текущий SSH TCP и TCP443/2053/2096/8444. Порт TCP8443
добавляется при выборе WARP.
TCP80 открыт для ACME, UDP443 — для Hysteria2. Для наборов 49/73/98/146
установщик открывает только выбранные дополнительные TCP/UDP-порты из диапазона
30000–30126; конкретный список определяется набором и выходом. Если в панели
провайдера есть отдельный firewall, разрешите там выбранные порты тоже.
Установщик сам включает UFW, разрешает эти порты и запрещает остальные
входящие соединения и пересылку трафика. Итоговая проверка сверяет правила,
политики firewall и слушающие службы, включая сохранённый SSH-порт.
Firewall/security group в панели провайдера управляется отдельно: если он
включён, разрешите эти же порты там. Установщик не получает доступ к аккаунту
провайдера и не создаёт DNS-запись домена.
При выборе WARP его внутренний connector доступен только через loopback. Внешние неизвестные
службы, существующие VPN, Docker, сертификаты или firewall rules блокируют
установку. Повторная установка поверх работающего сервера не выполняется.
Текущий доступ SSH сохраняется; отключать пароли следует после проверки
второго независимого входа по ключу.

## Управление

Если установка была прервана, скопируйте и выполните команду целиком:

```bash
bash /opt/vpn-installer/install.sh --resume
```

Отдельно вводить `--resume` не нужно. Сохранённые ответы используются повторно.
Установщик показывает эту полную команду после ошибки или прерывания, когда
сохранены исходники и настройки для продолжения, а также при повторном запуске
поверх предыдущей установки.

```bash
# Повторно показать данные доступа
bash /opt/vpn-installer/install.sh --show-access

# Проверить установленный сервер, в том числе после перезагрузки
bash /opt/vpn-installer/install.sh --verify

# Показать безопасное пояснение сохранённых ошибок
bash /opt/vpn-installer/install.sh --diagnose
```

Данные доступа: `/etc/krysyuk-standalone/access.env` (root, 0600).
Закрытые журналы и отметки этапов: `/var/lib/vpn-installer/`.
Снимки транзакций: `/var/backups/`. При ошибке откатывается текущая транзакция;
успешные предыдущие этапы сохраняются для `--resume`. Снимки могут содержать
секреты — не публикуйте их и журналы.
Если процесс принудительно убит или питание исчезло посреди незавершённой
транзакции, может потребоваться восстановление по закрытому snapshot;
установщик не принимает такое состояние как успешную установку.

Ошибка теперь содержит название этапа, пояснение причины и способ исправления.
При лимите Let’s Encrypt выводится проверенное время следующей попытки в UTC;
смена почты и пересоздание VPS не снимают лимит для того же IP/домена.
При неподтверждённом откате или неизвестной причине сначала предлагается
безопасная диагностика. Она не меняет сервер и не выводит исходный текст
закрытых журналов, пароли или ключи. Сохранённые журналы помечены как
исторические: их наличие не доказывает текущую ошибку или состояние служб.

## Проверки и границы результата

Код проверяется Bash/Python проверками и автономными тестами. Установщик
проверяет сертификат, панель, подписку для трёх User-Agent, изоляцию WARP
в соответствующих режимах и
прикладные соединения окончательных XHTTP-профилей. `--verify` после реальной
перезагрузки проверяет восстановление служб. До неё reboot acceptance остаётся
`PENDING`. Установщик не перезагружает VPS автоматически.

В v1.1.3 добавлены проверки с искусственными ошибками копирования, записи,
подготовки конфигурации и сигналами HUP/INT/TERM. До первого этапа VPN
установщик готовит полное проверенное состояние; при обычном прерывании
удаляет только собственные незавершённые файлы. Certbot также отслеживает
созданные каталоги и ссылку, чтобы откат не блокировал повторный запуск.
Nginx получает отдельную проверенную политику перезапуска после аварии
с паузой пять секунд. Её проверяют на отдельной службе в GitHub Actions.

В v1.1.4 дополнительно проверены ошибки отката TLS, частичной записи XHTTP
и служб обновления сертификата, остановки ACME-таймера и публикации WARP
checkpoints. При неудачном возврате TLS-ссылки используемый сертификат сохраняется;
ошибки записи и обычные сигналы не оставляют ложную отметку завершения этапа.
Занятые служебные пути и имя пользователя XHTTP проверяются до установки пакетов.

В v1.1.5 успешный выход этапа и атомарную запись отметки контролирует один
процесс переднего плана. Обычный сигнал в этой точке сохраняет отметку и
останавливает установщик; следующий `--resume` не повторяет уже успешный этап.
Повреждённые отметки, ссылки и небезопасные журналы отвергаются до запуска этапа.
Откат панели и начальной конфигурации продолжает независимые шаги после ошибки,
а файлы работающей службы не заменяются, если её не удалось остановить.
APT update требует успешной загрузки индексов. Проверка SSH поддерживает
штатный запуск службы по запросу через `ssh.socket`.

В v1.1.6 проверки архива работают и при включённой оптимизации Python.
Установщик задаёт стабильный язык вывода команд и сбрасывает унаследованные
настройки запуска Python, чтобы перевод UFW и отключённые `assert` не меняли
результат проверки. Перед восстановлением файлов Certbot и служб обновления
сертификата требуется подтверждённое состояние остановки; ошибка связи с
systemd не считается таким подтверждением. Откат установки WARP-watchdog
продолжает независимые шаги при ошибке восстановления и не запускает частично
восстановленные файлы.

В v1.1.7 исправлен сбой, обнаруженный при настоящей установке с доменом:
в v1.1.5–v1.1.6 разделитель `·` в трёх начальных названиях был повреждён,
из-за чего этап создания шести профилей останавливался. Теперь генераторы
и проверка используют Unicode escape, а отдельные тесты выполняют настоящие
jq-фильтры и проверяют URI по независимо заданным названиям для IP и домена.
Если v1.1.5–v1.1.6 уже остановилась на этом этапе, не удаляйте её состояние
и отметки: потребуется проверенное восстановление трёх названий перед `--resume`.

В v1.1.8 все ответы и итоговое подтверждение собраны перед проверкой сервера
и установкой. До подтверждения пакеты не меняются, в том числе при отсутствии
`curl`. Этапы получают закрытый stdin; pip и Certbot запускаются без
интерактивных вопросов. При `--resume` сохранённые параметры используются
повторно без новой анкеты.

В v1.1.9 итоговая сводка и запрос `yes` убраны. После последнего ответа
установщик автоматически проверяет параметры и сервер, затем обновляет Ubuntu
и устанавливает VPN. Незавершённая анкета и неверные данные по-прежнему
останавливают запуск до изменения пакетов.

В v1.2.0 добавлен цветной мастер с нумерованными шагами и явным выбором
адреса: без домена по IP или с доменом. Неверный пункт меню запрашивается
повторно; обязательные пустые поля тоже. Запуск поддерживает короткую команду
`bash <(curl …)`. После последнего ответа установка по-прежнему автоматическая.

В v1.2.1 мастер предлагает «По IP-адресу» или «По доменному имени»
и меню SNI: «По умолчанию max.ru» или «Свой». После ввода своего имени сразу
выполняется проверка; неподходящий SNI можно заменить до начала установки.
Числовой IP сервера в меню не выводится. Остальные параметры задаются
автоматически; все новые профили без ограничения IP и устройств.
`--resume` сохраняет настройки уже начатой установки.

В v1.2.2 добавлен живой индикатор установки: полоса завершённых этапов,
название текущего этапа и время его выполнения. Индикатор работает также
во время проверки SNI и сервера. Подробные журналы остаются закрытыми.
В `TERM=dumb` терминале печатается строка состояния раз в десять секунд;
при перенаправлении вывода остаются обычные строки без анимации.

В v1.2.3 исправлено неоднозначное «0% — готово» после подготовительных проверок:
их результат выводится без процентов. Общая полоса явно подписана «Общий
прогресс», а завершение отдельного этапа отмечается на своей строке.

В v1.2.4 подсказки продолжения показывают полную команду на отдельной строке
с просьбой скопировать её целиком. Справка переведена на русский; команды
вывода реквизитов и проверки VPN также выделены отдельными строками.

В v1.2.5 добавлен выбор Let’s Encrypt/6 профилей или без сертификата/4 профиля
с объяснением HTTP до выбора. Сохранённый режим используется при продолжении;
старые настройки без такого поля сохраняют режим Let’s Encrypt. Добавлены
пояснения ошибок, время повтора после лимита CA и команда безопасной диагностики.

В v1.2.6 исправлено чтение корректных пустых shell-параметров `KEY=`.
В режиме без сертификата параметры Hysteria2 намеренно пустые; v1.2.5 ошибочно
останавливался на XHTTP с `ENV_SHAPE`. Настройки и реквизиты менять не нужно.
Регрессия проверяет настоящие блоки записи direct/dual и чтение их результата
в обоих режимах. Другие ошибки формата по-прежнему отвергаются и получают
отдельное пояснение вместо `UNKNOWN`.

В v1.2.7 успешная установка и успешная команда `--verify` отмечаются зелёным
заголовком с галочкой. При перенаправлении вывода, `TERM=dumb` или `NO_COLOR`
цветовые коды не добавляются. Формат реквизитов и `--show-access` сохранён.

В v1.2.8 перед установкой выбираются серверный выход и набор профилей.
Название начинается с имени, введённого в мастере. Расширенные наборы добавляют
46 или 70 вариантов на каждый выбранный выход в ту же подписку 3X-UI;
при выборе одного выхода его профили остаются единственными в подписке.
Установка проверяет конфигурацию, службы и выдачу ссылок для трёх приложений.
Работу каждого дополнительного профиля через конкретного оператора связи
нужно проверять с его мобильной сети отдельно.

В v1.2.9 пункт «Не использовать CloudFlare WARP» действительно пропускает
установку WARP и публикует только прямые профили. Для всех трёх пунктов меню
проверяются состав подписки, XHTTP и выбранные дополнительные порты.
Восстановление `--resume` проверяет уже завершённый выпуск сертификата и
настройку его обновления, если установка оборвалась до записи отметки этапа.
Ежечасная сверка сертификата повторяет обновление расширенных профилей после
сбоя их renewal hook.

В v1.2.10 выбор режима сертификата удалён. Новая установка всегда выпускает
доверенный сертификат Let’s Encrypt по IP или домену и использует HTTPS для
панели и подписки. Ранее сохранённый режим без сертификата автоматически не
превращается в HTTPS-установку при `--resume`.

В v1.2.11 мастер принимает необязательный контактный email для Let’s Encrypt
и сохраняет его при продолжении установки. Сбой команды при настройке
дополнительных профилей теперь обозначается постоянным кодом шага без вывода
аргументов или закрытого вывода команды. Если откат тоже не удался, сообщение
сохраняет код исходного сбоя и отдельно указывает код ошибки отката.

В v1.2.12 исправлен порядок дополнительных профилей в подписке: ссылки и
правила маршрутизации следуют выбранному набору, а Xray по-прежнему группирует
клиентов по портам. Это устраняет остановку `PORTFOLIO_MANIFEST_SELECTION`
при выборе 49, 73, 98 или 146 профилей.

Скорость и работу у конкретного провайдера проверяют с устройства пользователя.
Реальные импорты в мобильные приложения и устойчивость соединений не подтверждаются одним запуском
скрипта на VPS. Установка v1.1.2 без домена проверена на отдельном чистом VPS:
обновление Ubuntu, выпуск IP-сертификата, все этапы VPN, пробное продление,
публичная подписка и восстановление после реальной перезагрузки.
Проверка портов ограниченно ждёт завершения собственных UDP-тестов Xray;
успех требует точного набора разрешённых listener.
Доменный запуск v1.1.6 подтвердил обновление Ubuntu, выпуск доверенного доменного
сертификата, HTTPS-панель и WARP; он обнаружил описанную выше ошибку названий.
После точечного исправления названий и обновления исходников до v1.1.7 доменная
установка успешно завершилась через `--resume`: пробное продление с hooks,
публичная подписка для трёх приложений, TCP/UDP/DNS через шесть профилей,
вход в панель и настоящая перезагрузка проверены отдельно.
Изменения v1.1.3–v1.2.6 проверяются кодом и Linux-тестами с искусственными сбоями.
Новая чистая установка v1.2.6 с нуля в обоих режимах, мобильные GUI-импорты, независимые
внешние REALITY 24/24 и скорость остаются отдельными непроверенными этапами.
